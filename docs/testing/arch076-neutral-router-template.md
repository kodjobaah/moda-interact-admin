# Neutral routing template

Use System Controls → WhatsApp templates → Create template → Conversation wrapper → **Router — before a shop is selected**. Author platform-neutral static header/footer copy and keep exactly one `response.body` body slot. Save a new immutable source, generate translations through the existing workflow, review all 19 translated locales, then use the wrapper publication screen’s ROUTER audience to compare and activate all 20 locales. Changes require Clone as New and another reviewed activation.

ROUTER is independent of SHARED, AI and HUMAN. An absent ROUTER is **Not configured**. A configured pointer whose definition, locale review, hashes or neutral structure are invalid is **refused**; neither case borrows a branded layout. Activation uses the existing SUPER_ADMIN checks, versioned compare-and-swap and audit event. It does not activate or alter the normal shop layouts and does not register anything with Meta.

Router content permits static text and one body response slot only. Variable tokens, raw placeholders, checkout conditionals, product images and composite profiles are refused at authoring, compilation, saved-projection verification and activation. Selecting the audience does not silently remove incompatible content; edit it or use the explicit removal action before saving. The preview inserts an illustrative routing question without loading shop, customer, basket, checkout or media context.

Review static wording for neutrality. Admin validates structure; Background independently verifies the actual published projection and checks outer copy against its routing identity scope before sending. Shop-specific text and media are used only after verified shop selection through the normal shop AI/SHARED layout. Shared’s ordinary audience policy and published package are unchanged.

Validation uses the existing disposable PostgreSQL wrapper-publication harness, extended with independent ROUTER activation, concurrent CAS, audit and tampered-locale rejection. No live settings, translations, provider sends or deferred system tests are part of this implementation task.
